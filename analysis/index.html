What changed vs source seeds

  • Unified multiple AI-generated and original seed datasets into a single clean schema.
  • Customers expanded from ~100–500 fragmented sets → 350 with consistent fields (language, consent, wallet, geo, signals).
  • Merchants normalized to 100 across cafe, restaurant, bakery, pharmacy, salon, gym, grocery, dentist, dessert, wellness. “food” category mapped to restaurant.
  • Scenarios split into public (dev/demo) and holdout (organizer eval only). Added seasonal tags: lunch, monsoon, IPL, Diwali, Holi, summer, winter, pharmacy, discovery, edge cases (consent, distance, stock, closed, budget).
  • Weather full 7×24 hourly feed for Bengaluru (May window + synthetic variation).
  • Festivals / events table for dynamic context (Diwali, Holi, New Year, IPL, monsoon, summer, winter).
  • Catalog + static offers linked to merchants; margin & discount constraints explicit.
  • No third-party branding anywhere in files or docs.
  • Evaluator provided under eval/ for groundedness, constraint respect, decision match, localization, profit awareness.
  • Correctness checks: unique IDs, lat/lng in Bengaluru bounds, discount ≤ max, consent boolean, language codes valid, holdout disjoint from public.

Correctness checklist (passed)

  • All customer & merchant IDs unique
  • Coordinates within Bengaluru bounding box (~12.7–13.2 N, 77.4–77.8 E)
  • Every public scenario references existing customer_id and merchant_id
  • max_discount_pct ∈ [0, 40], min_margin_pct ∈ [5, 25]
  • marketing_consent is boolean; ~96% true
  • Language values restricted to en / hi-en / kn-en / te-en / ta-en / hi / kn
  • Labeled holdout is organizer-only; a blind copy (no answers) is available for practice/leaderboard
  • Evaluator smoke-tested with sample JSONL
